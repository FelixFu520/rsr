# Isaac 仿真性能排查

用中文说明证据、假设和结果。先读 [官方建议摘要](references/nvidia-performance.md)，按症状选相关条目，不把整份指南变成批量开关。

若主要问题是穿透、弹飞或接触质量，转到 [碰撞排查 skill](../isaac-collision-debug/SKILL.md)；若怀疑功能组合或版本限制，读取 [物理 FAQ skill](../isaac-physics-faq/SKILL.md)。

## 建立可比较的基线

- 先查项目说明、当前启动命令和生效配置。记录 Isaac Sim / Kit / PhysX 版本、实际物理后端、CPU/GPU、环境数量、刚体/关节与碰撞规模、物理步长、渲染和传感器频率。
- 从日志和运行时状态确认实际路径，不仅依据配置中的 `device` 字符串。区分 PhysX 与 Newton 等其他后端；本指南不直接证明其他后端的行为。
- 固定场景、随机种子、动作序列、步长与采集负载；将启动、资产加载、编译/烹饪和预热与稳定运行分开计时。
- 分别观察物理步、渲染、控制/规划、传感器读取、记录/I/O 的耗时。按问题报告吞吐、实时率（仿真时间/墙钟时间）、延迟分位数及内存；仅凭 FPS 或 GPU 利用率不能确定物理瓶颈。
- 只在不破坏任务依赖时做隔离实验。无头模式仍可能有相机渲染；关闭采集得到的速度只能代表该实验负载。

## 从证据选择实验

使用摘要中的编号记录候选原因，并说明为何与当前日志、时间分布或场景规模相符。优先选择改动小、可回退且能区分假设的实验；每轮改变一个因素或一个不可拆分的配置组合。

涉及具体 API、扩展名称或设置键时，查当前安装版本与相应官方文档。来源使用 `latest`，不是对项目版本的兼容承诺。需要片段时打开原文相应章节，再核对本机接口；不要凭摘要猜 API。无法联网时利用本机文档/代码核对并标明未验证项。

修改 stage 前定位实际活动的 PhysicsScene 和配置来源，不假定路径为 `/World/PhysicsScene`，不因示例调用 `Define` 而创建第二个场景。确认设置的生效时机以及 reset、重载 USD 或启动参数是否会覆盖它。

## 验证性能与任务质量

用相同工作负载比较前后结果，同时检查与任务相关的穿透、接触稳定性、关节/轨迹误差、任务成功率、传感器输出和状态同步。阈值优先沿用现有验收标准；没有标准时说明实际观察和局限。

不要把降频、改变物理步长、删除必要碰撞或停掉业务处理后的吞吐提升当成等价优化。无收益或质量退化时回退。没有可运行的 Isaac 环境时交付具体补丁或排查步骤，明确尚未实测，不用 stub 成绩推断真实仿真性能。

输出保持简洁：瓶颈证据、改动及适用条件、前后指标、质量验证、剩余不确定性。注明哪些结论来自 NVIDIA、哪些是本项目测量或待验证假设。

## Real2Sim2Real 仓库适配

仅在当前项目确为 Real2Sim2Real 时应用，并以当前 `AGENTS.md` 为准：

- 仿真与项目检查使用 Isaac `./app/python.sh`；不要用 `uv sync` 创建替代仿真环境。
- 物理运行时调参放在对应 simworld 后端；资产碰撞改动放在资产所属模块。不要为优化把 Isaac 专用字段塞进通用 ABC。
- 保留构造函数无仿真资源、Job 固定生命周期及 `finally: close`。测量逻辑不要扩张通用 BaseJob 职责。
- 新配置同步后端 Config、默认配置和适用示例；检查继承配置、secrets 与环境变量覆盖，报告生效值时避免泄露密钥。
- 修改代码后运行适用的 lint/检查；只有真实后端的可比运行才能证明性能收益。
