# `docs/<task>.md` 模板与索引更新

现有三份任务文档（`docs/physic_solver.md`、`docs/sorting.md`、`docs/fire_inspection.md`）都按下面的结构写。
读者是接手任务的工程师和审核数据的人：写实测数值、单位、命令和链接，不写过程叙事。逐次实验记录留在 git 历史和
debug 目录，文档只保留结论和仍有参考价值的失败方案。

```markdown
# <任务中文名>：<机器人> <场景> <动作>

更新日期：YYYY-MM-DD。

## 1. 任务介绍
一段话说明做什么、为什么。
### 1.1 流程          # 阶段图：init_world → … → finally: close，每阶段做什么
### 1.2 约束与验收口径  # 需求 → 实现及边界（原装机型、不用附着、门限来源与授权）

## 2. 当前结果
采集时间（UTC）、代码状态；表格：输出目录、数据集（episode/帧数/fps/时长/相机路数/分辨率/编码）、
渲染设置、物理（引擎、频率、步数、墙钟与分项）、Job 验收 N 项、独立校验 M 项；关键指标 实测 vs 门限。
未通过或对照组放 debug 并在此说明。

## 3. 设计选择
### 3.1 物理引擎与求解器   # 选了什么、理由、被否决的方案及证据
### 3.2 …                 # 控制方式、规划、感知、渲染等每个非显然的选择

## 4. 组成
模块表：SimWorld / Scene / Robot / Planner / Job / 辅助函数 → 后端名 → 实现文件链接。
迁移任务加“迁移对照”列（原项目对应类）和“迁移后的调整”列表。
### 4.1 脚本            # 脚本 → 用途

## 5. 资产
`assets/<Task>/` 目录树、大小、准备命令；来源表（源路径/仓库与 commit → 内容 → 许可证）；
对源资产的改动；依赖检查结果（如 unresolved 条目的解释）。

## 6. 依赖与安装        # 只有额外依赖时保留：包名与版本、用途、安装命令、验证命令

## 7. 配置
文件表（正式 / 调试 → 用途 → 输出目录）；主要字段 → 含义与取值理由。

## 8. 运行
从安装到正式采集与独立校验的完整命令；调试→正式顺序与预计耗时；GUI 打开方式；常用环境变量覆盖。

## 9. 输出与数据格式
输出目录树；`observation.state` / `action` 每一维的名称和单位；相机列表；`task` 字符串；`robot_type`。

## 10. 验收
Job 内检查表（检查 → 含义 → 本次实测）；前置检查；独立校验覆盖范围。

## 11. 问题与解决方案
| 现象 | 原因 | 处理 |

## 12. 局限
耦合方向、运动学近似、真值感知、episode 数量、未验证项。
```

## 同时更新的索引（每处只加一行或一小节）

| 文件 | 位置 | 内容 |
|---|---|---|
| `README.md` | “任务”表 | 任务、内容、物理、配置目录、文档链接 |
| `README.md` | 采集命令、输出约定、目录结构、资产目录列表 | 新任务的命令、`outputs/<task>/`、文件后缀、`assets/<Task>/` |
| `AGENTS.md` | 1.1 任务布局表 | 任务、后缀、资产目录、后端名 |
| `AGENTS.md` | CLI 约定的“任务入口” | 新任务的运行命令 |
| `pyproject.toml` | entry points 上方注释 | 任务文件后缀列表 |
| `core/default_settings.toml` | 各段注释 | 新后端字段与默认值 |
| `.gitignore` | `tests/*` 白名单 | `!tests/test_<task>.py` |

不改其它任务文档的内容。共享代码有行为相关的改动时，在受影响任务文档的“问题与解决方案”里加一行说明。
