## 3. 核心问题与解决方法

### 3.1 固定机器人基座被漏计，导致“已经释放”的误判

**现象：** 左臂松手后，旧统计显示机器人接触为 0，但包裹仍拱起，平台静置高度异常，右臂抓取也容易拉伸。

**根因与证据：** 导入的固定基座和相机碰撞体 `body_id=-1`，与世界静态物体相同。旧逻辑只统计机器人动态 body，因此漏掉固定根碰撞体，也可能把它们当成台面处理。使用实际凸碰撞网格审计旧缓存，发现有 19～54 个顶点距基座表面不超过 2 mm，最近约 0.5 mm，确实处在接触包络内。证据见 [robot_base_contact_audit.json](../outputs/debug/robot_base_contact_audit.json)。

**修复：**

1. Runtime 保存活跃接触的 shape ID，按导入机器人的 shape 范围统计全机器人接触。
2. 将固定机器人根碰撞体单列为 `robot_root`，从台面类别中排除。
3. 新增 `scene.platform_target_xy`，在原平台范围内调整任务落点；机器人、平台和碰撞几何的位置保持原配置。
4. 保存固定根的世界凸几何、粒子半径及 shape margin，在实际静置状态用全部顶点和面中心复核间距，并要求在线全机器人接触为 0。

**效果：** 初次前侧落点候选的平台静置高度降至约 18.17 mm，包裹平展；独立基座间距为 26.047 mm。最终采用另一组连续可达目标后，正式轨迹的实际平台静置基座保守间距为 **4.366 mm**，仍大于 **1.000 mm** 接触包络。该数值来自实际仿真缓存，不是离线平移预测。

这项修复解决了释放判断和静态挂碰问题，但尚不足以单独解决右臂抓取；修复后的首个完整候选仍在右臂提升时拉伸超限。

### 3.2 包裹平展后，沿用旧偏心抓点导致右臂拉伸

**现象：** 旧拱起状态筛出的右抓点 `[-35,+55] mm`，用于新的平展包裹后，在 36.2667 s 出现边长比 **1.305218 > 1.3**。该时刻台面和基座接触均为 0，不能继续归因于挂住基座。

**定位：** 减少补夹仍未解决。hold 改为 0.64 rad，在 36.35 s 超限；缓慢放宽至 0.63 rad，在 36.7167 s 超限，且超限边已包含衣物网格。问题涉及抓点与整体受力，单独降低闭合量不够。

**修复：** 基于当前包裹形状重新选择抓点，并联合筛查平台落点、出料目标及整段 IK。检查包含抓取、提升、转运、下放和撤离，保持正常关节支路、关节限位与夹爪朝向。

- 平台 Y=-0.94、旧出料 Y=-0.876 时，右臂中心抓取没有找到连续路径。
- 同一平台上，Y+25 mm 局部抓取完成了右半程，证明减少偏心有效；该试验从缓存近似恢复，仍标为 `accepted_demonstration=false`。
- 联合调整为 **平台 `[0,-0.93]`、出料 `[-0.55,-0.84]`、右抓点偏移 `[0,0]`** 后，中心抓取具有正常右臂支路的连续路径。

**效果：** 最终完整运行的右臂三个在线持握检查点 RMS 约为 **31.696／31.471／31.326 mm**，均低于 37.413 mm；完整抓取、转运、放手与输送通过。减夹反馈虽保留启用，最终左右臂 `peak_grip_relief_rad` 均为 0，不能把此次成功归功于反馈实际介入。

筛查证据见 [平台／出料组合 IK](../outputs/debug/center_grasp_place_ik_scan.json)；局部试验边界见 [independent_local_audit.json](../outputs/debug/right_flat_center_probe/independent_local_audit.json)。

### 3.3 把 TCP 高度当成指垫底边高度，抓取深度失准

**问题：** 原生夹指包含金属凸碰撞体和白色指垫，闭合时最低点随角度变化。TCP 高度不能直接代表指垫底边。平台交接后包裹高度也会变化，固定使用初始抓取高度可能过深或夹持不足。

**修复：**

- 用原生 FK 标定闭合角度对应的指垫底边到 TCP 偏移，以 `grasp_pad_bottom_m` 控制真实最低位置。
- 右臂重抓时，读取抓点周围约 ±30 mm 的当前衣物表面 q90 高度，再结合绝对压入量、相对压入比例和最低高度计算底边。
- 最终参数为底边最低 15 mm、绝对压入 20 mm、相对比例 0.3；正式运行实际选出的右臂底边为 **18.356 mm**。
- 独立审计全部 3409 个物理帧，对 8 个原生夹指碰撞体检查所有包裹顶点及面中心。

**效果：** 全帧独立几何穿透最大 **0.936 mm**，低于 1.5 mm。在线接触报告的采样穿透是另一种统计，正式结果中约为 1.463 mm，也低于门限；二者没有混用。

原生闭合角度必须按真实几何解释。例如 0.64／0.65／0.675 rad 对应净夹缝约 11.816／9.819／4.823 mm。直接照搬参考版本夹缝推定 0.65 rad 足够的局部试验，在 34.15 s 丢失抓取。

### 3.4 60 Hz 缓存漏掉 mimic 约束的子步尖峰

**问题：** USD 中存在 PhysX mimic 配置，并不意味着迁移到 MuJoCo 后已正确生效。只检查每帧关节状态，还会漏掉帧间短时误差。

**证据：** 旧候选每帧 32 个刚体子步，60 Hz 缓存中的误差约 0.0125 rad；逐原生子步检查却在约 14.054 s 发现 **0.03098 rad** 峰值，超过 0.03 rad 门限。

**修复：**

- 在原生 MuJoCo 中建立并检查实际等式约束，使用 CPU 双精度连续状态求解。
- 最终每个 VBD 步执行 4 个刚体子步，32 个 VBD 步组成一个 60 Hz 物理帧，即每帧 128 个刚体子步，原生 dt 为 **1/7680 s**。
- mimic time constant 设为 0.00027 s，impedance 设为 0.9998，并核对本机求解器参数及时间步下限。
- 保存每个原生子步的残差；独立检查记录数量、有限性和最大值。
- 对批量执行与逐步执行进行边界状态等价回归；修复轨迹写盘读取错误配置对象的问题。

**效果：** 正式记录覆盖 **436224** 个原生子步，最大残差 **0.001309 rad**，低于 0.03 rad。机器人原质量、惯量和力矩上限保持原配置。

### 3.5 摩擦修改范围过大，混淆了平台问题与输送问题

**问题：** 全局降低台面摩擦曾使旧包裹更平展，但同时改变入料带、出料带及被错误分类的固定基座，无法据此证明只是平台摩擦过高。相关完整候选在左臂闭合阶段即失败。

**修复：** 按碰撞体角色分别配置摩擦，固定根不再归为台面；`platform_friction=0.1` 只作用于真实平台 shape。全程材料保持固定，不在释放阶段切换摩擦。

本机 Newton 实现采用几何平均：`mu_effective = sqrt(mu_particle * mu_shape)`。因此最终参数的含义为：

| 接触对象 | 材料参数 | 与包裹的有效摩擦系数 |
| --- | --- | --- |
| 包裹粒子 | 1.4 | 作为混合输入 |
| 原生夹指 | 约 2.85714 | 2.0 |
| 入料／出料带 | 0.5 | 约 0.83666 |
| 平台 | 0.1 | 约 0.37417 |

保存实际材料数组与 shape ID，独立验收确认参数确实作用到正确对象。增大摩擦可以改善保持，但不能代替抓点、深度和释放几何的修正。

### 3.6 阶段切换与撤离轨迹造成额外拉扯

**问题：** 按每阶段实测 TCP 误差反复重设目标，可能累积轨迹偏移；松爪时继续下降、或用关节空间直接回 READY，也可能让已张开的夹指扫过包裹。

**修复：** 阶段目标以连续的上一段命令目标衔接；转运使用 3 s 五次曲线，提升 4 s，下放目标为支撑面上方 0.13 m。释放持续 4 s，最终 `release_lowering_m=0`；撤离使用经过检查的笛卡尔路径。

允许支撑后放手，但仍要求完整包裹占地落在目标支撑范围、标签朝上、全机器人接触为 0，并记录实际释放下落量。没有通过放宽拉伸、形状或穿透门限来换取流程成功。

### 3.7 独立几何审计太慢，阻碍完整复核

**问题：** 袋衣间距的点到三角形全量遍历约需 6.45 s／帧，完整复核耗时较长。

**修复：** 在 `package_geometry.py` 增加 NumPy AABB 树，用包围盒距离的保守下界剪枝；叶节点仍使用原精确点到三角形算法。保留全部顶点、面中心及原门限，不新增依赖。

**效果：** 三份真实平展／持握／转运帧与原算法的最大差值均为 0，耗时降至 0.28～0.46 s／帧，提速 **14.2～22.8 倍**。随机、退化三角形及远质心大三角形反例纳入回归。证据见 [surface_distance_benchmark.json](../outputs/debug/surface_distance_benchmark.json)。

### 3.8 局部成功、残留目录和视频可播放，均不足以证明正式数据合格

**问题：** 局部恢复可能改变初始条件；中断目录可能没有完整结果；`completed` 也不能单独代表验收成功。视频正常播放只能证明编码可读。

**修复：**

1. 局部恢复明确标为诊断，记录恢复起点及 `accepted_demonstration=false`。
2. 用独立运行目录、结果标记和会话检查点区分试验；中断且未写出缓存的运行只记录日志或人工终止说明。
3. 正式源必须从初始状态连续运行并通过完整流程，渲染入口默认拒收失败源。
4. 先完成物理调试，再回放同一源轨迹录制四路 RGB；回放时冻结物理步进，核对资产、拓扑、质量、碰撞几何、材料和配置。
5. 独立复核物理指标、逐帧 state／action 时间对齐、四路视频完整解码及文件校验和，随后发布正式目录。

正式 LeRobot 数据由同一 60 Hz 物理源按 15 Hz 取样。视频时间戳为 0～56.7333 s；终端物理样本为 56.8 s，按现有采样契约不重复加入终端视频帧。

### 3.9 配置继承中的列表合并导致复现参数失真

**问题：** 项目父子配置会合并列表，直接把出料向量改为 `[-0.55,-0.84]`，可能与父值拼接成四个元素，造成配置校验失败或参数含义错误。

**修复：** 对覆盖向量显式使用 `@reset`，例如 `outfeed_target_xy="@reset [-0.55, -0.84]"`。以实例化后的四个组件有效配置核对正式配置与成功运行快照。

更新正式 collect 配置前，旧候选冻结到 [collect_before_success.toml](../outputs/debug/config_snapshots/collect_before_success.toml)，并修正其历史调试继承入口；核对前后有效参数一致，避免新参数反向改变旧试验含义。

### 夹爪画面错位的后续修复
